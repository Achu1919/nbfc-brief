## Soft Glass Motion: a design-language kit for Jetpack Compose

Soft Glass Motion is a calm, tactile UI style for Android:
- ink-on-mist colour
- frosted glass chrome floating over a soft sky gradient
- capsule controls
- iOS-style critically damped springs
- one light haptic for each user intent

This kit gives you the numbers, the rules and working Compose code, so that a developer or an
AI coding agent can start a new app in this style.

> It was inspired by studying a commercial app's interaction design. Every value here is our own:
> it was re-measured, rounded to our own grid, or re-chosen. Brand assets (fonts, logos, icons,
> colours, shaders, code) are excluded.

### Principles

1. **Ink, not colour.** One ink colour carries all the hierarchy, used at 100 / 50 / 30 / 14 / 7 / 5 %
   alpha. Colour is kept for meaning: accent, success, danger, warning and list hues.
2. **Glass is chrome, content is paper.** Bars, pills and floating controls are glass: a blurred
   backdrop, a translucent tint, a 1 dp rim and a soft ring shadow. Content cards are calm,
   translucent white panels with no blur.
3. **Capsules everywhere.** Controls are 44–48 dp capsules or circles. Cards use 20–24 dp radii.
   The checkbox fill is a squircle.
4. **Springs for motion, tweens for opacity.** Position, size and scale use near-critical springs
   (ζ ≥ 0.86 for big moves). Alpha and colour always use short tweens. Only accents bounce.
5. **Everything is interruptible.** Every animation retargets from its current value. Nothing
   queues, and nothing blocks input.
6. **Reduced motion is a variant, not a gate.** It swaps slides for crossfades. State changes
   happen exactly as they do with full motion.
7. **One haptic per intent.** A `tick` for selection, a `thump` for commitment and a `rise` for
   rare celebrations.
8. **Prove it frame by frame.** Each transition is tested on a paused clock: the landing frame
   must equal the settled frame, nothing may flash, and seams are checked by pixel measurement.

### How to use the kit

- **Humans:** read `foundations/`, then `motion/`, then `components.md`. Copy
  `compose-starter/` into your project and follow `compose-starter/SETUP.md`.
- **AI agents:** load `DESIGN-LANGUAGE.md`, which merges every Markdown file into one, as
  context. Then copy the starter code. Treat the numbers as tokens and the rules as constraints.
- Rename the package `design.softglass` to your own. Replace the palette hex values with your
  brand, but keep the colour roles and alpha ladder.

### Sky backdrop

The sky backdrop is one vertical gradient plus two radial glows, drawn **inside** the blur source:
- **Light stops** at 0 / .30 / .60 / .76 / 1: #66748F → #A3B0C8 → #DAE2EE → glow #F1F4F9 → deep #B7C2D6.
- **Dark stops:** #070A11 → #111723 → #1E2636 → glow #2B3550 → deep #151B29.
- **Smoothing:** interpolate each pair of stops with smoothstep over 10 sub-stops, so the gradient
  is C¹ with no visible Mach bands.
- **Glows:** radial glows at (0.82 w, 0.38 h) and (0.12 w, 0.62 h).

### Rules
- Only animate between colours with `animateStateColor`: it animates a 0..1 progress and reads
  both end colours fresh. This keeps a theme switch from tweening stale colours.
- Selection is an ink capsule with `onInk` text. Never use the accent for selection.
- The accent belongs only to: the today ring, the profile tint, the confirm check, and links on
  ink (`accentOnInk`).

## Typography

There are two families plus a mono, all under SIL OFL. They are **not bundled**; see `compose-starter/SETUP.md`.

- **Inter (variable)** is used for all UI text. Labels use weight **560**, between medium and
  semibold, because capsule labels need a little more weight than 500 to hold up on glass.
- **Newsreader (variable, opsz axis)** is used for display headings only: weight 500 with
  `opsz` = 28. An italic is available for emphasis.
- **JetBrains Mono** is used for monospaced numbers and debug UI.

| Token | Family | Size / line | Weight | Tracking | Notes |
|---|---|---|---|---|---|
| `display` | Newsreader | 28 / 34 sp | 500 | −0.01 em | screen titles ("Today") |
| `displayItalic` | Newsreader Italic | 28 / 34 sp | 400 | −0.01 em | emphasis in headings |
| `title` | Inter | 16 / 22 sp | 400 | −0.01 em | row titles |
| `body` | Inter | 15 / 20 sp | 400 | −0.005 em | body, inputs, switcher pills |
| `meta` | Inter | 13 / 18 sp | 400 | 0 | metadata, counts; `tnum` tabular figures |
| `label` | Inter | 14 / 18 sp | 560 | −0.005 em | segments, chips, buttons, undo bar |
| `mono` | JetBrains Mono | 13 / 18 sp | 400 | 0 | |

### Rules
- Colour text from the ink ladder (`ink`, `inkSecondary`, `inkTertiary`). Text colour is never
  part of the style.
- Counts and times always use `meta`, whose tabular figures stop numbers from jittering as they change.
- Completed items: the title fades to ink 38 % while a strike-through draws (see `motion/choreography.md`).
- The profile initial is the display serif at a **fixed 21 dp** size (`21.dp.toSp()`), so it does
  not scale with the system font size inside its fixed 44 dp circle.
- Widgets: plan for about 5.8 dp per character at 13 sp when sizing text to fit.

## Elevation and glass

### Ring shadows (no blur)
Shadows are **stacked, expanding outline rings** of the shape:
- Each ring is drawn only outside the shape (clipped by the shape's outline).
- Each ring is offset downwards by `dy`.
- The rings are cached per size in `drawWithCache`.
- This is cheaper and more stable than `Modifier.shadow`, and it looks identical in screenshots.

| Level | Spread | dy | Strength | Rings | Use |
|---|---|---|---|---|---|
| `Low` | 6 dp | 2 dp | 0.10 | 6 | chips, small controls |
| `Mid` | 14 dp | 5 dp | 0.13 | 9 | pills, circle buttons, composer, undo bar |
| `High` | 26 dp | 10 dp | 0.18 | 12 | drag ghost, floating panels |

Per-ring alpha = strength / rings × 1.6 (× 1.8 for the animated `liftShadow`). The base colour is `glassShadow`.
Apply the shadow **before** clip and fill.

### Glass recipe (control)
The modifier order is: shadow → clip → blur fill (or the fallback colour) → tint → 1 dp rim.

- **Rim:** a 1 dp stroke with a vertical gradient from `glassRimTop` to `glassRimBottom`. Its
  alpha is a lambda, so the rim can fade out while a chip fills.
- **Under reduced motion** (or when blur is unavailable), controls use the opaque
  `glassControlFallback`.

### Blur tokens (Haze)

| Token | Value |
|---|---|
| Library | `dev.chrisbanes.haze:haze` 2.0.1, using `hazeSource` / `hazeEffect` (or the `hazeBlur` helper) |
| Quality | Performance mode (half resolution); `noiseFactor = 0` (no grain) |
| `ChromeBlur` | 16 dp (top bar) |
| `FrostBlur` | 26 dp, saturation × 1.15 through a colour matrix, then `glassTint` (composer, floating panel) |
| `SearchBlur` | 30 dp (search frost: paper tint at 52 % light / 60 % dark, scrim 0.90) |
| `OverlayBlur` / dim | 16 dp; dim 0.18 light / 0.40 dark |
| `FocusBlur` / dim | 24 dp; dim 0.30 |
| `ExpandDim` | 0.16 |
| Capture card | window blur 20 dp + scrim 0.16, or scrim 0.34 when window blur is unavailable |

#### Rules
1. **Never animate the blur radius.** Fade glass in and out with layer alpha, because
   re-blurring every frame is expensive and shimmers.
2. The backdrop (sky) must be drawn **inside** the `hazeSource`:
   `Modifier.hazeSource(state).skyBackdrop(colors)`. Otherwise the glass blurs transparency and looks grey.
3. Glass is for one level of chrome. Do not stack glass on glass: a menu over glass uses `glassSolid`.
4. One `HazeState` per screen, provided through `LocalHazeState`. A null state means no blur, so
   use the fallback colours.
5. While the navigator is moving (`LocalNavMoving`), blur can be frozen (`LocalBlurFrozen`) to save frames.

### Edge masks
- **Top bar (`GlassEdgeTop`):**
  - The blur and tint stay at full strength down to the bar's solid height minus 20 dp. Below
    that, both fade out over 30 dp, with a 12 dp tail.
  - It overflows downwards **without taking layout height**, so lists scroll under it.
  - With no blur, `glassChromeFallback` at 85 % is drawn under the same mask.
- **Bottom fade (`bottomFade`):**
  - Content fades out over 36 dp above the composer, down to a floor of 0.25.
  - With the composer collapsed: 28 dp, floor 0.45.
  - It is an offscreen layer with a DstIn gradient. A 10 dp soft "clear" zone sits below.
- **Chip rows (`horizontalEdgeFade`):** a 24 dp DstIn fade, applied only on a side that can still scroll.
- **Every mask uses fractional stops with smoothstep easing.** A linear two-stop mask shows a
  bright Mach band at its end, so verify masks with the row-luminance test in `verification.md`.

### Lift
- `LiftScale` 1.03 for a dragged row; `ExpandLift` 1.015.
- `liftShadow` animates from Low towards Mid.
- `StackScale` 0.92 for a card stacked behind another; `EnterOffset` 12 dp.

## Springs, easing and press feedback

### Spring maths (iOS-style parameters)
Springs are specified the way a designer thinks: by **response** (the period of the undamped
oscillation, in seconds) and **damping ratio ζ**. Convert to Compose (mass 1):

```
stiffness k        = (2π / response)²
dampingRatio       = ζ                     (Compose's spring(dampingRatio, stiffness))
damping coeff c    = 2ζ√k
peak overshoot     = exp(−ζπ / √(1 − ζ²))   for ζ < 1, else 0
settle (ζ = 1)     ≈ 6.638 / ω  at 1 % tolerance, ω = 2π / response
settle (ζ < 1)     ≈ ln(100) / (ζω)        (1 % envelope)
```

```kotlin
fun stiffnessFor(response: Float) = (2f * PI.toFloat() / response).pow(2)
fun <T> iosSpring(response: Float, dampingRatio: Float, visibilityThreshold: T? = null) =
    spring(dampingRatio = dampingRatio, stiffness = stiffnessFor(response), visibilityThreshold = visibilityThreshold)
```

#### Damping rules
- **ζ ≥ 0.86 for moves longer than about 40 dp.** A large overshoot reads as wobble.
- **ζ 0.80–0.82 for short moves**, where a hint of life is welcome.
- **ζ 0.58 only for accents**: the check, the confirm and the pick pop. This is the only bounce users should notice.
- Opacity and colour **never** use springs.

#### Opacity rules
- Entrance alpha **starts 40–60 ms after the motion begins**, so the element is already moving when it appears.
- Exits are **120–150 ms with no delay**. Get out of the way fast.
- Colour changes animate a progress value (`animateStateColor`) and never the colour itself.

### Depth tokens (`Depth`)
Blur values: ChromeBlur 16, FrostBlur 26 (saturation 1.15), SearchBlur 30, OverlayBlur 16 (dim 0.18 / 0.40),
FocusBlur 24 (dim 0.30), ExpandDim 0.16.

Fade masks:
- BottomFade 36 dp with floor 0.25;
- collapsed 28 dp with floor 0.45.

Lift and entrance: LiftScale 1.03, ExpandLift 1.015, EnterOffset 12 dp, StackScale 0.92.
A new item enters 24 dp lower and at scale 0.94, then settles on Snappy.

### Press feedback (`Press.kt`)
- **`SoftPress` indication** (installed as `LocalIndication` by `AppTheme`):
  - an ink wash at **7 % peak**, in over 80 ms and out over 180 ms;
  - drawn **inside the node's bounds only**: a circle if the node is square (within 1 dp),
    otherwise a 12 dp rounded rect;
  - never a ripple, and nothing ever draws outside the control.
- **`pressScale(source, pressed)`** on `Quick`. Values:
  - buttons and circle controls: 0.94;
  - pills and chips: 0.95;
  - the generic default: 0.96;
  - rows: 0.98;
  - the checkbox mark: 0.9.
- Under reduced motion `pressScale` is off; the wash stays.
- Presses are counted, so with multi-touch the wash stays until the last finger lifts. Each
  change retargets from the current alpha.

### Implementation rules
1. **Read animated values only in draw or layout lambdas** (`graphicsLayer {}`, `drawBehind {}`,
   `offset {}`), never in composition. Then animation causes no recomposition.
2. **Everything is interruptible.** Use `Animatable.animateTo` from the current value, cancel the
   previous job, never queue, and never block input while animating.
3. **Exact ends.** After a spring finishes, snap the value to exactly the target, so the last
   animated frame equals the settled frame. Tests check this; see `verification.md`.
4. Use one clock per choreography when you can (one progress value `k`, with derived per-element
   curves). This beats N independent animations that can drift apart.

## Choreography

Every transition, with its numbers. `k` is a single 0..1 progress value unless stated
otherwise. All alphas and offsets are read in `graphicsLayer`. "Reduced" is the reduced-motion
variant (see `reduced-motion.md`).

### 1. Navigator: push and pop (`nav/StackNavigator.kt`)
- **One clock:** a single float `x` on `Smooth` (0.50 s, ζ 1.0). It is the top screen's offset
  as a fraction of the width.
- **Push:** in the same frame as the stack change, `x = 1`, then x animates to 0. The top screen
  sits at `x·w`, and the screen beneath at `−¼·w·(1 − x)` (quarter-width parallax).
- **No scale and no dimming.** The backdrop never shows at the edges.
- **Pop:** the same `x` animates 0 → 1. The arrow, system back and the predictive-back commit
  all call the same `pop()`.
- **Predictive back:** `x` follows `BackEventCompat.progress` directly. A cancel springs back to 0.
- **Covered screens stay composed** but are drawn with alpha 0, are hidden from semantics and
  take no input. The screen under a pop is ready on frame 0, so nothing pops in late.
- **Keyboard:** focus is cleared and the IME hidden in the same frame as the push or pop.
- **Measured landings** (16 ms frames): push 528 ms, arrow pop 544 ms, gesture pop 512 ms.
- **Reduced:** the same `x` drives a 150 ms crossfade, which lands at 176 ms.

### 2. Search morph (`patterns/SearchMorph.kt`)
- **One progress `k`** on `Smooth`, so there is no overshoot and every edge moves monotonically.
- **Pill geometry:**
  - The pill's rect is interpolated from the 44 dp search circle in the header to the dock: the
    full width minus 20 dp on each side, 48 dp tall, sitting 10 dp above max(IME, nav bar).
  - The magnifier glyph travels with it and ends 14 dp from the pill's left edge.
- **Inside the pill:** the hint text and the 34 dp close button fade in over k 0.45 → 1.
- **Header:** fades out with smoothstep(k / 0.7) and lifts 14 dp.
- **Composer:** fades out over k / 0.6.
- **List behind:** drifts 20 dp and dims to 65 %.
- **Frost:** a 30 dp blur layer whose **alpha** follows k. The radius is never animated.
- **Empty state:** rises 12 dp and scales 0.94 → 1 over k 0.5 → 1. Suggestion chips appear after k 0.8.
- **Results** use `reverseLayout`, so the newest match sits just above the dock, near the thumb.
- **IME tracking:** the dock follows the keyboard inset frame by frame, within 1 px.
- **Predictive back** scrubs k down by up to 30 %; on commit it closes on `Smooth`.
- **Haptics:** a `tick` on open and on close.
- **Reduced:** a 200 ms iOS ease-in-out tween with no travel (fade only).

### 3. View switcher: pill stagger (`patterns/ViewSwitcher.kt`)
- **Trigger:** a 48 dp glass circle, bottom-left. The pills spring up **out of it**,
  left-aligned with it, one by one.
- **Geometry:** pills are 48 dp tall, 56 dp step, and sit 10 dp above the button.
  Transform origin is bottom-left.
- **Per-pill transform:**
  - `translationY = (1 − k)·travel`;
  - `scale = 0.35 + 0.65·k`;
  - `alpha = min(1, 2.2·k)`.
- **Open:** springs at 0.42 s / ζ 0.72, staggered **34 ms bottom-up** (the nearest pill first).
- **Close:** springs at 0.30 s / ζ 1.0, staggered **22 ms top-down**.
- **Picking a pill:** the picked pill lingers for 110 ms and pops 1 → 1.08 → 1 (pick pop
  0.28 / 0.55, then back on the close spring), and folds last.

  also the tap shield.

### 4. Theme circular reveal (`theme/ThemeReveal.kt`)
1. On tap, PixelCopy the window. This captures exactly what is on screen, including blur and any
   reveal already in flight.
2. In the same state batch, switch the theme underneath and draw the snapshot on top.
3. Punch an antialiased **DstOut circle** into the snapshot. It grows from the toggle's centre
   to the farthest corner + 2 px, over 500 ms with ease (0.2, 0, 0, 1), and lands at frame 32
   (528 ms).
4. The system-bar icon style flips once the circle has covered the whole status bar.

- **A tap mid-reveal** re-snapshots the mixed frame and reveals again from the button. It
  retargets; it never queues.
- **The toggle glyph:** the sun/moon morph (0.35 s / ζ 0.90).
- **Reduced:** the snapshot fades out over 200 ms (landing at 224 ms), and the bars flip at half.

## Reduced motion

`LocalReducedMotion` = **the in-app "Reduce motion" setting OR the system animator duration scale
being 0**. It is provided by `ProvideMotion(userPrefReduceMotion)`, which observes
`Settings.Global.ANIMATOR_DURATION_SCALE` live.

### Rules
1. **It selects a variant. It never gates state.** The same state changes happen in the same
   order, with a different animation spec. Code paths stay identical, so tests cover both.
2. **Slides become crossfades.** Travel, scale and parallax are removed; only alpha remains.
3. **Bounce becomes calm:** `Pop` → `Quick` (`Springs.accent(reduced)`).
4. **Press scale is off.** The soft ink wash stays.
5. **Glass uses opaque fallbacks** where blur would animate (`glassControlFallback`).
6. Haptics are unchanged. They are not motion.

### Variant table

| Transition | Full | Reduced |
|---|---|---|
| Navigator push/pop | slide + ¼ parallax on Smooth | 150 ms crossfade (lands ≈176 ms) |
| Search morph | Smooth geometry morph | 200 ms ease-in-out fade, no travel |
| View switcher | staggered springs | 150 ms fades |
| Theme reveal | 500 ms circular reveal | 200 ms snapshot fade (lands ≈224 ms) |
| Checkbox fill | Pop | Quick |
| Composer collapse | Morph | fade-through 75 + 75 ms |
| Launch entrance | rise + stagger | 150 ms fade |
| Undo bar | slide + fade | 150 ms fade in, 120 ms out |
| Capture card | rise 48 dp on Glide | 150 ms fade, no travel |
| Press | scale + wash | wash only |
| Sheets / panels | spring morph | 150 ms tween |

### Testing
Run every transition test twice, with reduced motion off and on, and assert the same end
state. Check that the reduced variant has no translation: compare bounding boxes across frames.

## Haptics

There are three patterns, all ours, in `motion/Haptics.kt`. Every vibration goes through
`LocalHaptics`, and the rule is **one haptic per user intent**.

| Pattern | Definition | Fallback (no amplitude control) | Feel |
|---|---|---|---|
| `tick` | `VibrationEffect.createOneShot(12 ms, amplitude 140)` | `HapticFeedbackConstants.CLOCK_TICK` | light selection click |
| `thump` | `createOneShot(24 ms, amplitude 220)` | `HapticFeedbackConstants.CONFIRM` | firm commitment |
| `rise` | waveform of 12 entries: gaps of 38 ms and pulses of 9 ms (first gap 0); pulse i has amplitude `255 × (0.2 + 0.8 × (i/5)^1.5)` | `CONFIRM` | a short crescendo; a celebration |

### Gating
- Fire nothing if the system "Touch feedback" setting (`Settings.System.HAPTIC_FEEDBACK_ENABLED`)
  is off, **or** if the in-app haptics toggle is off.
- Vibrate with `VibrationAttributes.USAGE_TOUCH`, so the system's touch-intensity setting applies.
- Haptics are not motion, so reduced motion does not change them.

### Map

**tick**, for selection and small state changes:
- toggles and switches; changing a segment of the segmented pill
- chips and filter chips
- toolbar tool buttons
- opening and closing search
- adding an item (once per add, not per field)
- tapping to expand the composer
- a swipe action crossing its threshold, in either direction
- reorder: picking a row up, and each slot change while dragging
- calendar: tapping a day, releasing the pull, turning a page, hovering over a new day while dragging
- the view switcher closing, going back or folding
- unchecking an item
- opening a menu; tapping the theme toggle
- the profile circle
- snooze option rows

**thump**, for commitment:
- completing an item (checkbox)
- starting a long-press drag on the calendar
- saving from the capture card
- confirming a delete
- finishing a planning session ("Done")

**rise**, which is rare and earned:
- the last open item cleared ("all done"), 250 ms after the completion thump
- a successful drop when rescheduling on the calendar

### Rules
- Never fire two haptics for one gesture. For example, a pill tap that also changes the page is
  one `tick`, not two.
- Fire on the **state change**, not on the touch-down. A swipe ticks when the threshold is
  crossed, and a drag ticks when the slot changes.
- Fire `rise` at most once per moment, never in a loop.

## Verification: proving the motion is right

Motion bugs (end snaps, a flash on the first frame, seams, ripples leaking outside a shape) are
often invisible at full speed and obvious one frame at a time. Every pattern in this kit was
signed off with the techniques below. They run as JVM unit tests on Robolectric with native
graphics, with no device needed.

### 0. Setup
```kotlin
// app/build.gradle.kts

        unitTests.isIncludeAndroidResources = true          // fonts and resources in screenshots
        unitTests.isReturnDefaultValues = true
        unitTests.all {
            it.systemProperty("robolectric.pixelCopyRenderMode", "hardware")
            it.systemProperty("roborazzi.test.record", "true")
            it.systemProperty("shots.dir", rootProject.file("out/shots").path)
        }
    }
}

    testImplementation("org.robolectric:robolectric:4.17")
    testImplementation("io.github.takahirom.roborazzi:roborazzi:1.76.0")
    testImplementation("io.github.takahirom.roborazzi:roborazzi-compose:1.76.0")
    testImplementation("androidx.compose.ui:ui-test-junit4")
    debugImplementation("androidx.compose.ui:ui-test-manifest")
}
```
Test class header:
```kotlin
@RunWith(RobolectricTestRunner::class)
@GraphicsMode(GraphicsMode.Mode.NATIVE)
@Config(sdk = [36], qualifiers = "w411dp-h891dp-420dpi")
class SomethingMotionTest {
    @get:Rule val rule = createAndroidComposeRule<ComponentActivity>()
    private val dir = File(System.getProperty("shots.dir") ?: "build/shots").apply { mkdirs() }
    private fun frame(): Bitmap =

```
Notes:
- Haze renders its fallback (no real blur) on Robolectric. Test blur geometry with the
  fallback tint, then check the real blur on a device.
- Freeze anything time-driven that is not under test (rotating hints, clocks) with a system
  property, so frames are deterministic.

### 1. Frame-step tests (paused clock)
Pause the clock, start the motion, step 16 ms at a time, capture every frame, and assert:
1. **No first-frame flash.** Frame 0 equals the state before the motion, or is a legitimate
   first step, never a jump to the end.
2. **No end snap.** Once the animated values have reached their targets, every later frame
   equals the settled frame. This catches blur swaps, inset changes, and a final
   `scale(1f)` that differs from 0.9999.
3. **Monotonic where it should be.** An opacity tween never reverses. A spring may overshoot
   by at most the amount predicted by `SpringMath.peakOvershoot(ζ)`.

```kotlin
@Test fun pushLandsOnTheSettledFrame() {
    rule.setContent { ProvideMotion(false) { AppTheme { StackHost(/* … */) } } }
    rule.mainClock.advanceTimeBy(2_000); rule.waitForIdle()
    rule.mainClock.autoAdvance = false

    rule.onNodeWithContentDescription("Open details").performClick()
    val frames = buildList { repeat(60) { rule.mainClock.advanceTimeBy(16); add(frame()) } }
    rule.mainClock.advanceTimeBy(2_000); val settled = frame()

    // first frame at which the navigator reports "done" (expose it via a test probe or semantics)
    val landing = frames.indexOfFirst { regionDiff(it, settled) < 0.5f }
    assertTrue("never settled", landing >= 0)
    for (i in landing until frames.size)
        assertTrue("frame $i snaps after landing", regionDiff(frames[i], settled) < 0.5f)
    filmstrip("push", frames)
}

/** Largest mean |Δ| (0–255) over an 8 × 8 grid: a localised snap cannot hide in a global mean. */
fun regionDiff(a: Bitmap, b: Bitmap): Float {
    val gw = a.width / 8; val gh = a.height / 8; var worst = 0f
    val ra = IntArray(gw); val rb = IntArray(gw)
    for (gy in 0 until 8) for (gx in 0 until 8) {
        var sum = 0L
        for (y in gy * gh until (gy + 1) * gh) {
            a.getPixels(ra, 0, gw, gx * gw, y, gw, 1); b.getPixels(rb, 0, gw, gx * gw, y, gw, 1)
            for (i in 0 until gw) for (s in intArrayOf(16, 8, 0))
                sum += abs(((ra[i] shr s) and 0xff) - ((rb[i] shr s) and 0xff))
        }
        worst = maxOf(worst, sum / (3f * gw * gh))
    }
    return worst
}
```
Also run each test under **reduced motion** (`ProvideMotion(userPrefReduceMotion = true)`) and
assert that the end state is identical. Reduced motion changes the path, never the outcome.

### 2. Filmstrips
Write every Nth frame into a grid, so a reviewer (human or agent) can see the whole motion in
one image.
```kotlin
fun filmstrip(name: String, frames: List<Bitmap>, every: Int = 3, scale: Int = 4, crop: Rect? = null) {
    val picks = frames.filterIndexed { i, _ -> i % every == 0 }.take(30)
    val src = crop ?: Rect(0, 0, frames[0].width, frames[0].height)
    val tw = src.width() / scale; val th = src.height() / scale
    val cols = minOf(10, picks.size); val rows = (picks.size + cols - 1) / cols
    val out = Bitmap.createBitmap(cols * (tw + 4), rows * (th + 4), Bitmap.Config.ARGB_8888)
    val c = Canvas(out)
    c.drawColor(android.graphics.Color.MAGENTA)   // gutters: never confused with app pixels
    picks.forEachIndexed { i, f ->
        val x = (i % cols) * (tw + 4); val y = (i / cols) * (th + 4)
        c.drawBitmap(f, src, Rect(x, y, x + tw, y + th), null)
    }
    FileOutputStream(File(dir, "$name-filmstrip.png")).use { out.compress(Bitmap.CompressFormat.PNG, 100, it) }
}
```
Crop to the component when the motion is small (a checkbox or a chip), and use `scale = 1` there.

### 3. Pixel checks (with examples)

#### 3a. Seam check on glass edge masks
A fading glass edge must have no visible band. Take one column of luminance through the fade
and check both the step and the slope.
```kotlin
val col = (0 until fadeEndPx).map { y -> lum(bmp.getPixel(x, y)) * 255f }
val steps = col.zipWithNext { a, b -> b - a }
assertTrue(steps.all { abs(it) < 1.5f })                                     // no hard step
assertTrue(steps.zipWithNext { a, b -> abs(b - a) }.all { it < 0.08f * 255 / fadePx }) // no kink
```
Run this in light, dark and reduced-motion modes. A smoothstep mask passes; a linear mask
fails the slope check at both ends.

#### 3b. Classifying theme-reveal frames
During the circular reveal, every pixel must be either the **old** theme's frame or the **new**
theme's frame. A pixel matching neither is a blend artefact or a flash.
```kotlin
for (f in frames) {
    var neither = 0
    for (i in px.indices) if (!near(f[i], oldF[i]) && !near(f[i], newF[i])) neither++
    assertTrue(neither < ringPixels(radiusAt(f)))   // only the anti-aliased edge may differ
}
```
Also assert that the revealed area grows monotonically, and that the final frame equals a
fresh render in the new theme.

#### 3c. Press feedback stays inside its shape (0 px)
Press and hold a round control while frame-stepping (both tap length, about 100 ms, and
long-press length, about 600 ms), then release. Count the changed pixels **outside** the
shape (the circle plus 2 dp for a fill pop). The count must be **0** on every frame, which
proves there is no square ripple or rectangular indication.
```kotlin
val base = frame()
rule.onNode(checkbox).performTouchInput { down(center) }
repeat(40) { rule.mainClock.advanceTimeBy(16)
    assertEquals(0, changed(base, frame(), allowed = { x, y -> hypot(x - cx, y - cy) <= r + 2 * d }))
}
```

#### 3d. Correct capsule on the first frame
A sliding indicator (the segmented pill, the selected chip) must be at the selected segment on
the first composed frame, with no slide-in from index 0. Set the content with selection = 2,
capture without advancing the clock, and assert that the capsule's ink pixels lie inside
segment 2's bounds (taken from semantics).

#### 3e. Touch probe
Glass layers and edge masks must not steal touches. Inject a tap at points that lie inside the
visual fade but outside the control, and assert that the list item underneath received the
click. Log the hit-test results to a `.txt` file next to the screenshot.

#### 3f. Spring maths matches the runtime
Check that the design numbers (response, ζ, overshoot, settle time) are what Compose actually
runs.
```kotlin
@Test fun springMatchesAnalytic() {
    val token = Springs.Quick
    val anim = Animatable(0f)
    rule.mainClock.autoAdvance = false
    scope.launch { anim.animateTo(1f, token.spec()) }
    var t = 0
    while (t < 800) { rule.mainClock.advanceTimeBy(16); t += 16
        val expected = SpringMath.stepResponse(t / 1000.0, token.response.toDouble(), token.damping.toDouble())
        assertEquals(expected, anim.value.toDouble(), 0.01)
    }
}
```
Also test `stiffness(response)` ↔ `response(stiffness)` round trips, the overshoot is 0 at
ζ ≥ 1, and the settle times in the springs table.

### 4. Contact sheets
A small Python script (PIL) assembles named screenshots from `out/shots/` into labelled sheets.
- Rows of `(caption, file, scale)`; an optional crop is written in the name as `name#x0,y0,x1,y1`.
- A dark neutral background (#222228), 24 px gaps and 26 px captions.
- Light/dark pairs side by side. Filmstrips go full width.

One sheet per feature is what a reviewer looks at first. `reference/` holds examples from our
own implementation.

### 5. Checklist before shipping a motion
- [ ] A frame-step test covering both the first frame and the settled frame
- [ ] The same test under reduced motion: same end state, no travel
- [ ] Interrupt mid-flight (tap again at 50 %): no jump, and it continues from the current value
- [ ] A filmstrip committed for review (light and dark)
- [ ] 0 px press leakage on round controls
- [ ] Touch probe through any glass or edge fade
- [ ] One haptic per intent (assert with a fake `Haptics` that counts calls)

### Wiring it up (minimal)

```kotlin
class MainActivity : ComponentActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        enableEdgeToEdge()
        super.onCreate(savedInstanceState)
        setContent {
            val reveal = remember { ThemeReveal() }
            val dark = reveal.overrideDark ?: isSystemInDarkTheme()
            ProvideMotion(userPrefReduceMotion = false) {           // motion/Motion.kt
                AppTheme(darkTheme = dark) {                         // theme/Theme.kt
                    ThemeRevealHost(reveal) {                        // theme/ThemeReveal.kt
                        StackHost(                                   // nav/StackNavigator.kt
                            root = "home", keyName = { it }, fromName = { it },
                        ) { key, nav ->
                            val haze = rememberHazeState()
                            CompositionLocalProvider(LocalHazeState provides haze) {
                                Box(Modifier.fillMaxSize().hazeSource(haze).skyBackdrop(AppTheme.colors)) { /* list */ }
                                // chrome (top bar, composer) goes here, OUTSIDE hazeSource, using glass modifiers
                            }
                        }
                    }
                }
            }
        }
    }
}
```

Rules that the code relies on (see `../motion/` and `../foundations/elevation-glass.md`):
- The backdrop must be drawn inside the `hazeSource`. If it is not, glass blurs transparency.
- Read `Animatable.value` only inside `graphicsLayer {}` / `drawBehind {}` / `offset {}` lambdas.
- `LocalReducedMotion` only picks animation variants. Never use it to gate state changes.
